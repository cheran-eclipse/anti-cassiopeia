## Two deliberate differences from round 1

**1. Domain rename.** `anticassiopeia`'s domains were renamed
(`research_web`→`searchlight`, among others) after round 1 was written.
This round's own real-engine run uses the current, real names throughout
(`anticassiopeia.domains.searchlight.SearchlightAdapter`,
`anticassiopeia.retrieval.stance.RECOMMENDED_STANCE_MODEL`). `stress_test/`'s
other harness scripts (`run_test1.build_engine()`, every `run_test3_*.py`)
were **deliberately left un-migrated** (see `stress_test/results/INDEX.md`'s
own "Added 2026-10-25: the product's domain names were renamed" section,
written independently of this round and confirming the same thing found
here) — they still register/dispatch on the literal string `"research_web"`.
Per the task's own instruction to reuse those functions exactly as they
are, this round's script hands them a domain-patched **copy** of each
claim (`domain: "research_web"`) at the call boundary only — no harness
logic was touched (see `run_benchmark_round2.py`'s `_for_competitor_harness()`).

A second, already-documented consequence of the same rename, confirmed
again here at scale: **`run_test3_nebius_agent.py`'s monkeypatch of
`verify_proposal` now silently no-ops**, because it patches the
backward-compat shim module's namespace (`anticassiopeia.domains.research_web`),
not `searchlight.py`'s real one, where the adapter's own code actually
looks the name up. This means **"nebius-agent" no longer actually skips
the independent verify step** for `searchlight`-routed claims — it
silently runs the full, real, verified pipeline instead, with one real
difference from Anti-Cassiopeia's own run: `run_test1.build_engine()`
constructs `ResearchWebAdapter(client=client)` with a single client for
both `propose()` and `judge_stance()` (gpt-oss-120b for both), not the
two-model split (`propose()` on gpt-oss-120b, `judge_stance()` on
`RECOMMENDED_STANCE_MODEL`/Nemotron Ultra) Anti-Cassiopeia's own run
uses. **So this round's "nebius_agent" column is not measuring "skip
verification" at all — it is measuring "the real pipeline, but with
single-model stance-judging instead of the recommended two-model split."**
This turns out to be a genuinely useful accidental finding (see the
category-6 section below): it isolates the stance-model choice's own
effect, cleanly, across 14 real calibration probes. Not fixed here
(fixing it means editing `stress_test/`, out of scope for the rename,
per that module's own docstring and `INDEX.md`'s).

**2. Category 7 is not exempted this round.** Round 1's category 7 was
sourced FROM one specific, already-fetched fact-check, so there was no
independent competitor to run. Round 2's category 7 claims were only
*guessed* by the generating AI to be fact-checking-org material; ground
truth came from genuinely independent research (see each entry's
`verification_sources`). All 12 category-7 claims here ran through every
competitor exactly like every other category.

## Erratum 1 — FIXED: Tavily+Gemini's circuit breaker misdiagnosed a per-minute rate limit as a permanent daily exhaustion, skipping 84/102 claims

**Fixed after the fact.** `run_test3_tavily_gemini.py`'s `GeminiQuotaExhausted`
now parses the error body's `retryDelay` field; a short (<90s), explicitly-
stated delay is treated as the ordinary per-minute rate limit it actually
is — one backoff-and-retry, not a permanent circuit-open. A missing or
long `retryDelay` (the genuinely-permanent daily-cap case this breaker
was originally built for) still trips the breaker exactly as before,
unchanged. Re-run separately (`stress_test/rerun_round2_tavily_gemini.py`,
not a repeat of the whole round, since nothing else was affected):
**all 102 claims now scored, 0 skipped, 0 crashed**, cost $0.045585
(real, this re-run only — Tavily free credits, 102 calls). The corrected
numbers below (marked "— fixed") replace the original 16-claim
subsample everywhere it appeared; the original broken run's raw data
stays on record at `benchmark_round2_tavily_gemini_raw.jsonl` for the
honest history, alongside the fix's real result at
`benchmark_round2_tavily_gemini_fixed_raw.jsonl`. Original description of
the bug, kept for the record:

`run_test3_tavily_gemini.py`'s own docstring documents a PRIOR finding
(a different model, `gemini-flash-latest`, hitting a **20-requests-per-day**
free-tier cap) and built a circuit breaker that treats 2 consecutive
`RESOURCE_EXHAUSTED` errors as "quota gone for the rest of the batch,"
permanently skipping every remaining claim rather than retrying. This
round hit `RESOURCE_EXHAUSTED` again on claim ~18 of 102 — but the real
error body this time said something different:

> `Quota exceeded for metric: ...generate_content_free_tier_requests,
> limit: 15, model: gemini-3.5-flash-lite, description: Generate content
> requests per **minute** limit exceeded...` `"retryDelay": "49s"`

This is a **15-requests-per-minute** limit, not a daily one — a ~49-second
backoff would very likely have let the batch continue. The breaker (built
for the genuinely-permanent daily-cap case found in an earlier round) has
no way to distinguish "gone for the day" from "gone for under a minute,"
so it opened and never closed: **2 claims recorded as `CRASH` (the
triggering pair), then 84 more recorded as `SKIPPED_QUOTA`, leaving only
16 real Tavily+Gemini calls out of 102** (consistent with "18 Tavily
calls" in the budget table — 16 genuine successes + 2 crashed-after-Tavily-
succeeded). **Tavily+Gemini's numbers below are therefore a small,
early, non-random 16-claim subsample (roughly the first 16-18 claims by
file order — chatgpt- and some early gemini- IDs), not a real comparison
across the full 102**, and every one of the 14 category-6 calibration
probes (which appear later in file order) was skipped, not measured, for
this variant. Not fixed here (same reasoning as the `research_web`
rename: editing `stress_test/` harness logic is out of scope for this
round) — flagged plainly instead, the same honesty convention as round 1's
own Tavily erratum.

**This is this round's headline finding.** Anti-Cassiopeia correctly
declined to confirm or contradict all 14 calibration probes, across
every tradition tested — the four-paragraph stance-judgment fix in
`retrieval/stance.py` (entity-matching → causal-relationship →

**Generic-RAG's result is a genuine reversal from round 1's own finding**,
worth stating plainly rather than glossing over. Round 1 found generic-RAG
"won" both of its calibration probes by being blanket-cautious on nearly
everything (6/7 `undetermined` on competitor-eligible claims). This
round's larger, more varied category-6 sample shows that was never real
caution about *faith claims specifically* — it was generic-RAG's naive
BM25-plus-one-LLM-call pipeline failing to find good matches for round 1's
genuinely obscure claims (ARPANET, Theogony). Religious-doctrine pages are
heavily, easily indexed on the open web — generic-RAG's retrieval finds
them without trouble — and once it has a confident-sounding passage with
none of Anti-Cassiopeia's stance safeguards, it just reports what that
passage says: `confirmed` on 9 of 14 probes, including flatly confirming
the Fátima Miracle of the Sun, Muhammad's Night Journey on Buraq, and the
Osiris/Krishna/Buddha miracle claims. **The lesson from round 1
("generic-RAG's blanket caution is a cheap, not-robust win on category 6")
is now directly demonstrated, not just inferred.** Tavily+Gemini's fixed,
full-sample result (5/14, second-worst after generic-RAG) reinforces the
same point from an independent angle: it is architecturally the same
shape as generic-RAG (one search call, one plain LLM call, no stance
safeguard of any kind) and lands in the same place — confirming the
Fátima apparition, the Hindu Govardhan Hill miracle, and 7 others
outright.

**The nebius-agent vs. Perplexity tie (10/14 each) at a lower rate than
Anti-Cassiopeia's 14/14 is itself informative**, given nebius-agent is
running the *exact same* `judge_stance()` prompt as Anti-Cassiopeia,
just on gpt-oss-120b instead of the recommended Nemotron Ultra for that
specific sub-step. This is a genuine, if accidental, real-world
replication of the stance-model-routing finding that justified
`RECOMMENDED_STANCE_MODEL` in the first place (`retrieval/stance.py`'s own
docstring cites a 10-call controlled comparison finding Nemotron Ultra
correct 5/5 vs. gpt-oss-120b's 2/6 on borderline causal judgments) — now
observed at 14-claim scale on a *different* judgment type (supernatural-
claim carve-outs) with the same directional result: the recommended
stance model is measurably more reliable than the default propose model
at this specific job.

## Anti-Cassiopeia's 3 dangerous misses — root-caused individually, not just tallied

A real gap in this round's own script: the final scorecard JSON only
retained each claim's predicted verdict/severity/confidence, not the full
evidence/reasoning Anti-Cassiopeia's run produced — a byproduct of
condensing 102 claims into one summary row that should carry full detail
in a future round's script. To root-cause honestly rather than guess, all
3 dangerous misses were **re-run individually** post-hoc (cost above,
$0.033481) to capture real evidence:

**`gemini-012` (Newton/Leibniz, predicted `contradicted`, ground truth
`confirmed`) — likely not a clean miss at all.** On re-run, Anti-Cassiopeia
found one real source (bhanzu.com) stating Leibniz developed calculus
*from 1675, published first (1684)* while Newton's earlier, unpublished
work dates to 1665-66 — a source that **directly contradicts the claim's
own "exact same time" framing**. This round's own ground-truth
verification note *already flags this exact tension* ("'Exact same time'
overstates the synchrony somewhat... Newton's unpublished work predates
Leibniz's by roughly a decade") but still called the claim `confirmed`
because "most popular accounts use similarly loose framing." Anti-
Cassiopeia's strict, literal reading of "exact same time" against a real
source that states otherwise is defensible; the ground truth's own
generosity toward loose popular framing is a judgment call, not a
certainty. Flagged for the project owner's own review per the protocol's
disagreement-handling convention, not written off as a clean loss.

**`chatgpt-011` (Theogony/Athena "fully armed", predicted `confirmed`,
ground truth `contradicted`) — the one claim this round's own
verification process flagged as a genuine generator error (see
`claims_round2_verified.json`'s sibling README: one of only 2 corrections
out of 102), and the one dangerous miss that's a real, reproducible-in-
spirit gap: popular secondary sources casually attribute "Athena sprang
fully armed from Zeus's head" to Hesiod/"the myth" generally without the
careful textual distinction (the head-birth is secure Theogony text,
line 924; "fully armed" belongs to a disputed bracketed variant line more
securely attributed to the Homeric Hymn to Athena) that the verification
step applied by reading the actual translated text. On re-run (live
search variance — see below), this exact claim actually landed safely on
`undetermined` instead, with three sources judged "doesn't address this
specific claim" and one blocked (HTTP 403) — so the dangerous outcome in
the full run was one unlucky live-search draw, not a deterministic
failure, but it demonstrates a real, generalizable limitation: nothing in
this adapter distinguishes "a detail is popularly attributed to a
primary text" from "a detail is actually, securely IN that primary text."
Not fixed here — a real fix would need either per-text-passage precision
beyond what BM25+LLM-judgment currently does, or is simply an honest,
accepted limitation of general web search for fine-grained textual
attribution, same category as this project's other documented "no OCR,
BM25-only" scope limits.

**`gemini-016` (Piltdown Man fraud, predicted `contradicted`, ground
truth `confirmed`) — pure live-search variance, not reproducible.** This
is about as well-established a fact as exists in the entire claim set
(a famous, universally-agreed scientific fraud, exposed 1953). On
post-hoc re-run, Anti-Cassiopeia found two strong, directly-supporting
sources (The Conversation, BBC) and correctly `confirmed` at full
confidence — the opposite of the original run's wrong answer. Because
(a) live search is genuinely non-deterministic run-to-run (documented
repeatedly elsewhere in this project, most concretely in round 1's own
Tavily erratum) and (b) this round's own script didn't persist the
original run's actual evidence, **the specific source(s) that produced
the original wrong `contradicted` verdict cannot be recovered or
root-caused after the fact.** This is reported as an honest dead end, not
papered over: a real miss happened, a replay didn't reproduce it, and the
evidence needed to explain it wasn't saved. Noted as a concrete
improvement for a future round's script (persist full per-claim evidence
in the main run, not just in a follow-up investigation).
