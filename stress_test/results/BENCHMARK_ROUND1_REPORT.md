## The headline finding: a real, fixed bug, found by category 6 exactly as designed

**6b was the one claim Anti-Cassiopeia itself got dangerously wrong.**
"The Prophet Muhammad received divine revelations from the angel
Gabriel that were later compiled into the Quran" — a flat, unqualified
claim about a matter of faith — came back `CONFIRMED` at 0.90
confidence, on one real Wikipedia passage:

> "According to Islamic tradition, the revelation of the Quran to the
> Islamic prophet Muhammad began in 610 CE when the angel Gabriel ...
> appeared to Muhammad..."

The source itself hedges with "according to Islamic tradition" — it
reports a documented belief, not an assertion of the underlying
supernatural event as objective fact. `judge_stance()` didn't carry
that hedge through to the verdict, conflating "this is a real,
documented belief" with "this is a confirmed fact" — exactly the kind
of overconfident answer this project exists to prevent, on exactly the
claim type (matters of faith) the calibration-probe category exists to
catch. The companion probe (6a, resurrection) only passed because live
search found zero evidence that run — an accidental correct answer, not
a real epistemic judgment; a future run that found a similarly-hedged
"according to Christian tradition..." passage would have hit the
identical bug.

**Fixed** (commit `22d5677`): a third additive paragraph in
`retrieval/stance.py`'s `STANCE_SYSTEM_PROMPT`, same pattern as the
existing entity-matching and causal-claim fixes — distinguishes "passage
vouches for the claim as fact" from "passage reports what a tradition
holds," with an explicit carve-out for when the claim itself is phrased
as being about what a tradition believes. 3 new offline tests. Live-
verified: the exact failing case now resolves to `UNDETERMINED`; a full
regression re-run of all 9 round-1 claims found zero new misses caused
by this fix (claim 5 flipped from correct to a tie on re-run, traced to
genuine live-search source disagreement on discovery-date wording —
confirmed unrelated to this change, not a regression).

**Notable, not Anti-Cassiopeia's bug:** every other system except
generic-RAG also confirmed 6b, and Tavily+Gemini additionally confirmed
6a (resurrection) — the only system to get BOTH calibration probes
wrong. generic-RAG's own defensive posture (undetermined on nearly
everything, see below) is why it alone passed both by default.

## Other findings — real, diagnosed, deliberately NOT hacked around

**2 (ARPANET) and 7a/7b (both fact-check claims): conservative misses
traced to a retrieval gap, not a reasoning gap.** For claim 2,
`missing` reported: *"both the DuckDuckGo and Wikipedia search backends
returned nothing"* for the full claim sentence used verbatim as the
search query. For 7a/7b, either the same zero-results outcome, or real
pages were found but none contained the specific claim (`research_web`
found 3 real Wikipedia pages for 7b and the model honestly reported the
claim wasn't stated on any of them — general web search doesn't
specialize in surfacing a specific fact-checking org's own article for a
narrow, detailed claim). This is a genuine, generalizable limitation of
using the raw claim sentence as a verbatim search query, and of a
keyless generic web search backend with no fact-checking-org tuning —
already implicitly covered by `research_web.py`'s own documented
"generic, no domain tuning" scope. **Not fixed this round**: one
observed instance per case is not enough to safely redesign query
construction without risking a fix that only helps the literal claims
used to find it (the same discipline the protocol's own §3.6 demands).
Worth a dedicated, larger-sample investigation in a future round if this
pattern recurs.

**4 (Moon landing hoax): Anti-Cassiopeia went soft (undetermined) on a
well-settled false conspiracy claim — exactly the finding §1.4 says to
treat as seriously as a wrong confident answer.** Diagnosed by re-running
the claim in isolation: that re-run actually landed on a correct
`CONTRADICTED` (0.90), but on a *weak* source — a Wikipedia trivia
mention of a fictional movie character's line jokingly referencing the
moon-hoax conspiracy, not an authoritative debunking. The original
round run found nothing usable at all. Both outcomes trace to the same
root cause: `research_web`'s live search, with no domain tuning, isn't
guaranteed to rank an authoritative source (e.g. NASA's own rebuttal
page) above an unrelated page that happens to mention the topic in
passing — a real, honest, already-documented limitation of the BM25-
only, no-domain-tuning search step, not a new, fixable bug from one
observed case. **Separately notable:** `nebius-agent` (retrieval +
propose, no independent verify) confidently `CONFIRMED` this claim —
dangerously wrong, and a clean, real illustration of exactly the thesis
this whole project is built on: skipping the independent verify step is
not a safe shortcut.

**5 (Dead Sea Scrolls): correct on the scored run, a genuine disagreement-
zone tie on a later re-run** (not a miss in the original scorecard above,
but worth noting since it surfaced during the fix's own regression
check) — two real sources disagreed, plausibly on the exact discovery
year (1946 vs. 1947 both appear in real accounts), and the engine
correctly refused to pick a side rather than guessing. This is the
system's disagreement-handling working as designed.

## Structural note, not a competitor loss (per §2)

`ml_data`/`fpga_embedded` were not included this round, as locked by
the protocol: none of the 7 categories are shaped for those two domains
(they need an exact structured file + statistic, not a general-
knowledge claim), and comparing them against a generic competitor would
be apples-to-oranges. No claim was lost or skipped because of this — it
was never in scope.

## What generic-RAG's pattern actually shows

generic-RAG (the naive, undifferentiated baseline) answered
`undetermined` on 6 of 7 competitor-eligible claims, including 3 it
should have confidently confirmed (ARPANET, Theogony, Dead Sea Scrolls)
— a conservative-miss rate far higher than any other system. It "won"
both calibration probes by the same blanket caution that cost it
accuracy everywhere else. This is a useful data point for future rounds:
a system that refuses to commit on almost everything looks safe on a
calibration probe for the wrong reason, and the protocol's own §6
warning (category 6 is not about "winning") is exactly why this round's
scorecard separates that probe from the main tally instead of crediting
generic-RAG for it.
