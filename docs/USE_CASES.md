# Where Anti-Cassiopeia fits

Anti-Cassiopeia checks a claim against evidence a person can inspect and
returns `confirmed`, `contradicted` or `undetermined`, with the quote or
recomputation and its location. It never answers from a model's memory. That
shapes where it is useful:

- **Fits:** work where a wrong claim that sounds right costs more than a
  missing answer, and where a source exists (a document, a dataset, a report,
  or the open web).
- **Doesn't fit:** opinions and predictions, claims with no retrievable source,
  and anything that needs a model's general knowledge. In those cases it
  returns `undetermined`.

Each setting below has four parts: the workflow problem, how the engine
applies, what the repo shows, and what is not shown yet, with a test that
would show it. "What the repo shows" lists measured results only. Everything
else is the design's intended fit.

## Training and evaluation data

**Problem.** Candidate training sets, synthetic data and evaluation sets
contain many factual claims. Checking them by hand doesn't scale, and a
plausible but wrong claim in a training set teaches the error.

**How it applies.** Each claim gets a verdict with a quote and locator.
Confirmed and contradicted claims become labels with evidence attached.
Undetermined claims are held back and not guessed. The kept set is smaller but
each label can be traced to a source.

**What the repo shows.** On 88 independently verified open-web claims, it
answered 64 and was wrong on 2 (96.9% precision, range 89.3 to 99.1%). It held
back the rest. Cost was about $0.008 per claim in round 2 ($0.80 for 102
claims). The round 2 claim set itself was built this way: generated by three
AI tools, then each claim verified against sources by hand, and 3 of 102
generator verdicts were corrected.

**Not shown.** Any effect on a trained model. About 3% of answered labels are
wrong, so a sample should still be human-checked.

**Test that would show it.** Label a candidate set, human-check a sample of
each verdict class, then fine-tune on the kept labels and on the unfiltered
set, and compare both on a verified held-out set.

## Newsrooms and fact-checkers

**Problem.** A claim goes viral and needs a sourced answer quickly. "No source
found" is a legitimate finding, and a confident guess is the worst outcome.

**How it applies.** `searchlight` searches (Tavily first), fetches candidate
pages, checks each quote verbatim, and rolls the evidence up. It returns
`undetermined` when nothing settles the claim, and names what is missing.

**What the repo shows.** 12 claims shaped like published fact-checks (viral
misinformation, debunked myths, pseudoscience) were all answered correctly in
round 2. One round 1 claim (sunglasses and cancer) resolved to `contradicted`
from three Full Fact articles. All 14 faith-based probes were left
`undetermined`, the right outcome for a claim a source can't settle.

**Not shown.** Use inside a newsroom's workflow, breaking claims with few
sources, non-English claims, and pages behind paywalls or bot blocks (one round
1 claim stayed `undetermined` because its deciding source was bot-blocked).
Research-claim latency averaged about 6.8 seconds in Test #2 (7 claims).

**Test that would show it.** Run a month of one fact-checking outlet's
published claims through it, with the outlet's verdicts as ground truth.

## Research groups

**Problem.** Citations and reported statistics get repeated without being
re-checked. "The paper says X" and "the mean is Y" are both checkable.

**How it applies.** `searchlight` mode 1 fetches a cited page and matches the
quoted passage verbatim. `quant` recomputes `mean`, `median`, `p25`, `p75`,
`stdev`, `min`, `max` and `correlation` from the dataset, including compound
claims and multi-file datasets.

**What the repo shows.** Recomputation on 14 UCI datasets plus a held-out one.
In Test #1 it answered 2,498 `ml_data` claims at 99.7% precision (two bugs,
fixed the same day). On the 216 claims whose file is small enough to paste, the
current engine was wrong 0 times (against labels corrected for 25 stale
`air_quality.csv` claims, see [Open items](#open-items)). Given the same file
inline, `gpt-oss-120b` was wrong on 59 answers (66.7% precision), sonar on 48
(77.6%; it may also search the web), generic RAG on 55 and code-exec on 1. The
`gpt-oss-120b` errors are all on true claims: it estimates a statistic and
rejects a value that is within tolerance. 540 of 756 `ml_data` claims use a
file too large to paste.

**Not shown.** Statistics from tables inside published PDFs, paywalled sources,
and dataset formats beyond CSV. Percentiles use the exclusive method, which
differs from numpy, pandas and Excel defaults, so a claim's convention must
match.

**Test that would show it.** Take open-data papers with deposited datasets,
re-check each reported statistic, and compare with the authors' own numbers.

## Scientific institutions and labs

**Problem.** Specs, timing reports and instrument outputs are compared with
requirements by eye, and a misread table cell passes review.

**How it applies.** `silicon` parses Vivado timing summaries (WNS, TNS, WHS,
THS, per-clock figures, multi-corner reports) and CMSIS-SVD register maps, and
compares a stated figure with a requirement. Each piece of evidence carries a
source line. `substrate` does the same for datasheet ratings.

**What the repo shows.** 9 real Vivado reports from 7 public repositories, and a real
Espressif SVD file (ARM's example SVD has no peripherals). On 116 `silicon` claims with the same report
available to every system, Anti-Cassiopeia gave 0 wrong confident answers.
Code-exec gave 3, `gpt-oss-120b` with the report pasted in gave 4 and generic
RAG gave 7. All of the pasted-in model errors were labelled table misreads
(a rule-based label, checked by hand on a sample).

**Not shown.** Other EDA tools (Quartus, Yosys), instrument data formats, and
fields outside FPGA and hardware specs.

**Test that would show it.** Add a parser for one lab's report format and run
claims written by the engineers who read those reports.

## Government and public bodies

**Problem.** Statements about policy, budgets or statistics must match the
official documents, and a reviewer needs to see which passage supports a
statement.

**How it applies.** Documents are uploaded and a claim is checked against one
document, or against up to 10 pooled documents with one search, with the
citation naming the document and passage. `/verify/project` handles a bundle
of claims, each tied to its own document.

**What the repo shows.** Upload and project bundles were tested on two open-source
documents (ODrive, MIT, and NASA JPL's Open Source Rover, Apache-2.0),
including unknown and expired `document_id`s, oversize files and files with no
text layer. Pooled search has offline and server-level tests, not a test on
real documents.

**Not shown.** Official documents, long PDFs with tables, or multi-language
text. **Data handling matters here:** uploaded text is sent to a hosted model
provider (Nebius) for extraction and stance judgment, and uploads are kept in
memory for 24 hours in a single-instance deployment. Sensitive records need a
deployment with approved model hosting and persistent, access-controlled
storage; that isn't built.

**Test that would show it.** Take a public agency report and a list of
statements about it that analysts have already marked supported or not, and
compare.

## AI labs and agent builders

**Problem.** An agent states facts it hasn't checked, and the user can't tell
which ones.

**How it applies.** `POST /verify` and `POST /verify/compound` work as a tool
call before an agent answers. A non-confirmed result returns the missing
evidence, which the agent can use to search again or tell the user it can't
say.

**What the repo shows.** The verdict contract, calibration on faith-based
probes (14 of 14 `undetermined`, against 3 to 10 of 14 for systems using the
same search), and a compound-claim path whose negation bug was found and
fixed.

**Not shown.** Any effect on a live agent's answers.

**Test that would show it.** Run models with and without the verdict as
context on the same claims, and compare wrong confident answers. A third arm
of the document-fed control test is planned for this.

## Education

**Problem.** Claims in coursework are checked against course material by hand.

**How it applies.** A teacher uploads the text, and a claim is checked against
it, with the supporting passage shown.

**What the repo shows.** Only the generic upload path (see Government). Nothing
was measured on educational material.

**Not shown.** Everything about this setting. It is the weakest-evidenced fit
in this list.

**Test that would show it.** Upload a course text, check a set of student
claims, and compare with a teacher's marking.

## Space, defence and other high-consequence engineering

**Problem.** A part, a margin or a number in a report must match a
requirement, and a confident wrong match is expensive.

**How it applies.** `substrate` compares a stated rating with the requirement
and names when no rating exists. In the repo, a claim that a sensor survives
500 m is checked against its rated range converted to depth, with a
too-close-to-call margin of 5% for unit conversions. The QuSpin magnetometer
has no rating, so any depth claim stays `undetermined`, with the page that
shows it.

**What the repo shows.** The pattern on subsea hardware: BlueROV2, Bar30 and
Bar100XT ratings, including conflicting sources (a 200 m claim stays
`undetermined` where one document says 300 m and another 100 m).

**Not shown.** Any aerospace or defence document. It checks stated ratings
against requirements; it is not a test, a certification or a safety system.
Export-controlled or classified material shouldn't go to a hosted API.

**Test that would show it.** Run a requirements list against the datasheets
for the parts it names, with engineers' pass or fail marks as ground truth.

## Open items

- **Document-fed control test.** Finished for `fpga` and `ml_data`
  (`stress_test/results/DOC_FED_CONTROL_REPORT.md`). Gemini was not run, and
  the model-plus-Anti-Cassiopeia arm and the closed-corpus `searchlight` test
  are not done.
- **Stale labels.** 25 of the 872 file claims in the 1,000-claim sample (all
  `air_quality.csv`) had ground truth computed with the dataset's `-200`
  missing-value marker counted as data. They were relabelled with the
  independent oracle (an overlay file; the manifest is unchanged). Against the
  corrected labels the current engine is 100% on the 872 file claims, and the
  earlier saved pipeline run is 97.1%. The corrected labels rest on the UCI
  convention that `-200` means missing, which the claim text doesn't state.
  About 212 `air_quality.csv` claims in the full manifest are stale the same
  way.
- **Not tested in any of the settings above:** a real deployment.
